# Developer Explorer Bot

**Developer Explorer Bot** — Telegram-бот для поиска и изучения open-source проектов на GitHub.

Приложение позволяет находить репозитории по направлениям разработки, языкам программирования и ключевым словам. Поддерживает повторный поиск без дублирования результатов и сохраняет историю просмотренных проектов.

## Возможности

- **Поиск по направлениям:** Backend, Frontend, AI/ML, Data, DevOps, Mobile, Game Development.
- **Выбор языка программирования:** фильтрация проектов по языку.
- **Текстовый поиск:** поиск репозиториев по ключевым словам.
- **Повторный поиск:** получение новых результатов без повторов в рамках текущего поиска.
- **История просмотров:** сохранение и отображение последних 10 просмотренных репозиториев.
- **Информация о проектах:** описание, язык программирования, количество звёзд и форков, дата обновления, ссылка на GitHub.
- **Обработка ошибок:** уведомления о проблемах подключения и ограничениях GitHub API.

## Архитектура проекта

Приложение разделено на несколько компонентов:

```text
developer_explorer_bot/
├── data/
├── database/
├── handlers/
├── keyboards/
├── services/
├── tests/
├── main.py
├── requirements.txt
├── .env.example
└── README.md
```

- `data/` — справочники, callback-модели и состояния FSM.
- `database/` — подключение к SQLite и операции с историей просмотров.
- `handlers/` — обработчики сообщений и callback Telegram.
- `keyboards/` — формирование пользовательских меню.
- `services/` — интеграция с GitHub API.
- `tests/` — автоматические тесты.
- `main.py` — точка входа в приложение.

Для управления диалогами используется FSM. Конкурентные поисковые операции контролируются с помощью `asyncio.Lock` и проверки актуальности поиска.

## Установка и запуск

**Требования:** Python 3.14, Telegram Bot Token и GitHub Token.

### 1. Клонирование репозитория

```bash
git clone https://github.com/YOUR_USERNAME/developer_explorer_bot.git
cd developer_explorer_bot
```

Замените `YOUR_USERNAME` на имя владельца репозитория.

### 2. Создание виртуального окружения

```bash
python3.14 -m venv .venv
source .venv/bin/activate
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка переменных окружения

Создайте файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Укажите токены:

```env
BOT_TOKEN=your_telegram_bot_token
GITHUB_TOKEN=your_github_token
```

Реальные токены не должны публиковаться в репозитории.

### 5. Запуск приложения

```bash
python main.py
```

Бот запускается в режиме Telegram long polling.

## База данных

Для хранения истории просмотров используется SQLite.

База автоматически инициализируется при запуске приложения. История хранится отдельно для каждого пользователя.

По умолчанию файл `bot.db` создаётся в корневой директории проекта.

При необходимости расположение базы можно изменить с помощью переменной окружения `DB_PATH`:

```env
DB_PATH=/var/lib/developer-explorer/bot.db
```

При развёртывании на сервере рекомендуется использовать постоянное хранилище, чтобы история сохранялась после перезапусков и обновлений приложения.

## Тестирование

Для автоматического тестирования используется pytest.

Установка:

```bash
pip install pytest
```

Запуск:

```bash
python -m pytest -v
```

Тесты проверяют:

- Работу с GitHub API и преобразование данных репозиториев.
- Пагинацию и исключение повторных результатов.
- Сохранение и получение истории SQLite.
- Инициализацию и обновление схемы базы данных.
- Обработку ошибок HTTP и SQLite.
- Конкурентные поисковые запросы и состояния FSM.
- Конфигурацию приложения.

Тесты выполняются с использованием моков и временных баз данных, без обращения к реальному GitHub API.

## Безопасность и обработка ошибок

- Токены хранятся в переменных окружения и исключены из Git.
- SQL-запросы используют параметризованные значения.
- HTTP-запросы выполняются асинхронно с ограничением времени ожидания.
- Предусмотрена обработка сетевых ошибок и сбоев базы данных.
- Реализована защита от повторных запросов и устаревших callback.
- История просмотров изолирована по пользователям.
- При отображении истории учитывается ограничение Telegram на длину сообщения.

## Ограничения

Текстовый поиск возвращает до трёх новых репозиториев за одно обращение.

Для ограничения нагрузки на GitHub API поиск просматривает не более пяти страниц по 100 репозиториев за нажатие. После исчерпания доступных результатов пользователю предлагается начать новый поиск.
